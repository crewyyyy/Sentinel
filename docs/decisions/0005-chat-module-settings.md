# 0005: Настройки модулей по чатам

Базовый YAML остаётся настройкой оператора. Необязательные модули можно переопределить для конкретного управляемого чата через приватную панель: черновик, сводка и отдельное подтверждение. PostgreSQL хранит ревизию и аудит, не mutable Config и не browser state.

Режим запрещённой категории означает правило чата и запрос проверки. Он не подтверждает продажу, спам или наказание. Структурированные `policy_checks` сохраняются в assessment вместе с исходными сигналами и поступают в AI. При совпадении запрещённой категории создаётся pending-карточка независимо от малого риска.

Новая политика собирается тем же Analyzer, но получает отдельный hash-based ruleset ID из базового snapshot, чата, ревизии и overrides. Snapshot регистрируется транзакционно. Старые assessments и AI payload не обновляются; новые сообщения и правки читают выбранную ревизию из БД. Кэш содержит только неизменяемые скомпилированные экземпляры и ограничен 64 записями.

Права проверяются для выбранного чата при открытии, callback, подтверждении и доставке. Callback привязан к владельцу, destination, Telegram receipt и revision; панели ограничены сроком. Перезапись из устаревшей независимой панели блокируется проверкой версии под транзакционной блокировкой. Обязательные модули в Telegram доступны только для чтения.

Текстовые policy-модули используют общий ограниченный разбор контекста и matcher. Словари не содержат regex/DSL; сравнение нечувствительно к регистру. Неоднозначность и неполное покрытие требуют review, а не дают уверенный вердикт.
