# Автоподключение чатов

## Без ручного chat_id

Включено по умолчанию: `telegram.auto_discover_chats: true`; `chat_ids: []` допустим. Admin destination и numeric allowlist всё равно задаёт оператор. Для ЛС destination должен совпадать с разрешённым user ID. Откройте ЛС бота через `/start` до запуска/подключения: Telegram не даёт боту первым начать диалог.

1. Allowlisted администратор добавляет бота в группу/супергруппу и выдаёт статус администратора без прав санкций.
2. `my_chat_member` содержит настоящий `chat.id`, тип чата и `from.id` автора изменения. Другие люди не могут включить наблюдение простым добавлением бота.
3. Сохраняется только ограниченный кандидат подключения: chat ID, тип, redacted title, owner, время/ревизия и статус. Контент группы не собирается. Карточка отправляется только в ЛС владельца после проверки актуальных прав и приватности destination.
4. **Перед подтверждением оператор уведомляет участников** о целях, retention и внешнем AI-провайдере. Кнопка «Подключить» — явное подтверждение готовности; бот не выдаёт это за доказанную публикацию notice.
5. Callback проверяет owner, ЛС, реально отправленный message ID, ревизию/TTL, allowlist, текущие права администратора и статус бота. Одного username, `/admin`, пересланной кнопки или fake callback недостаточно.
6. Согласие и chat ID сохраняются в PostgreSQL. Только затем принимается новый доступный контент, создаются first-observed/MUST jobs и кейсы. YAML не меняется, restart не требуется.
7. После подтверждения исходная карточка меняется на «Чат подключён», после отказа — на «Подключение отклонено». Кнопки удаляются явной пустой клавиатурой, не `reply_markup: null`. При временной ошибке outbox повторяет доставку; сохранённое согласие не откатывается из-за ошибки оформления.

`/start` и `/chats` повторно ставят pending-карточки в outbox — в том числе после перезапуска или первоначально недоступного ЛС. Если права API временно не проверяются, активация запрещена; callback не блокирует FIFO навсегда, чтобы событие выдачи боту прав могло обработаться.

## Что не импортируется

Нет сканирования других групп, истории до установки или получения произвольной переписки. До согласия сообщения неизвестной группы отбрасываются до durable payload. После активации старый queued backlog с датой до согласия не принимается; свежая правка определяется по `edit_date`. Telegram timestamps имеют точность до секунды, более точный порядок внутри этой секунды не обещается. Контекст нового сообщения/reply может включать предоставленный Telegram родительский фрагмент, всегда с ограничением размера/coverage.

## Отмена и повторное добавление

`my_chat_member` с `left`/`kicked` отключает чат и отменяет pending-кнопки. Эффект применяется при обработке durable события, не синхронно с действием в Telegram. Новые бизнес-записи после отключения не создаются; ранее принятые обязательные проверки и retained evidence не уничтожаются. Старое событие/кнопка не возобновляет наблюдение. Повторное добавление auto-чата требует свежего подтверждения.

Явный ID в YAML — отдельное deployment-time согласие. После удаления inactive tombstone имеет приоритет над YAML; при новом событии присутствия бота явно настроенный чат может возобновить работу без auto-подтверждения. `auto_discover_chats: false` отключает новые заявки, но не отменяет уже одобренные чаты. Для отключения удалите бота/управляйте consent state осознанно, не выдавайте смену discovery flag за очистку данных.

## Хранение и обслуживание

- Заявки и их title/receipt: 24 часа, затем periodic cleanup. Неподтверждённые inactive tombstones без заявок также удаляются после 24 часов.
- Audit discovered/approved/rejected/disconnected: 90 дней.
- Одобренный managed-chat ID, approval metadata и inactive tombstone сохраняются для устойчивости consent/restart; содержимого сообщений в них нет.
- `managed_chats` и явный YAML объединяются чтением из БД, без конкурентно изменяемого Config/cache. Ошибка consent lookup не подтверждает входной update Telegram.
- Общая модель `/model` проверяет права во всех активных чатах, включая подключённые динамически. Пока активных чатов нет, bootstrap-команды доступны только numeric allowlist.
- `/chats` ограничивает показ/повторную отправку первыми 20. Pending card не гарантирована, пока у бота нет admin-статуса, админ не открыл ЛС или API недоступен.

Функция проверена fake Telegram + PostgreSQL: bootstrap без IDs, pre-consent/queued-backlog filtering, явный callback, owner/receipt/RBAC/expiry, restart, отказ ЛС, removal/rejoin и сохранность старых MUST jobs. Реальное добавление в вашу группу требует ручной проверки.
