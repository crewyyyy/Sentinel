# Проверка медиа

Модель: [fal-ai/imageutils/nsfw](https://fal.ai/models/fal-ai/imageutils/nsfw/api). Она возвращает `nsfw_probability`. Это оценка модели для изображения, не подтверждение нарушения и не общий детектор рекламы или насилия.

## Включение

1. Задайте `FAL_KEY` в приватном env, который использует Compose. Ключ не нужен текстовому AI и не заменяет `AI_API_KEY`.
2. Добавьте блок `media` из `configs/config.example.yaml` и установите `enabled: true`.
3. Уведомите участников о передаче изображений в fal.ai. Для ранее подключённых групп оператор отдельно согласует новый вид обработки.
4. Создайте backup, пересоберите образ и пересоздайте только сервис бота обычным способом из [operations.md](operations.md). Не запускайте второй poller. На старте применяется миграция `0006_visual_moderation`.
5. С разрешённого аккаунта отправьте боту фото или стикер в ЛС. Ожидается ответ на это сообщение с оценкой. `/status` показывает очередь медиа.

Результаты и уведомления об очереди используют Premium custom emoji из общего набора интерфейса. При явном отказе Telegram от custom emoji срабатывает резервное оформление без них; timeout/429 не вызывают немедленную повторную отправку.

В личке проверка доступна только `telegram.allowed_admin_ids`, если `media.private_replies: true`. Групповые администраторы вне этого списка не получают платный сканер автоматически. `ignore_admin_messages` действует в группах; личные запросы оператора он не отключает. На обычные личные текстовые сообщения сканер не отвечает.

## Что отправляется модели

| Медиа | Проверка |
|---|---|
| Фото, статический WebP-стикер, документ-изображение | Один PNG размером до 768×768 |
| Telegram animation / GIF, MP4, WebM-видеостикер | До трёх PNG-кадров, максимальная оценка из выборки |
| Векторный TGS-стикер или TGS custom emoji | Только Telegram thumbnail, пометка «Проверено превью» |
| Статический или видео custom emoji | `getCustomEmojiStickers`, затем обработка изображения или кадров |
| Нет превью, повреждённый или неподдерживаемый файл | «Не удалось проверить медиа», не безопасный результат |

Обрабатываются до восьми уникальных медиа на сообщение. Превышение отмечается как неполная проверка. Emoji из процитированного сообщения не сканируются автоматически. SVG и произвольные URL не открываются. Обычные видео, аудио и голосовые сообщения не входят в этот сканер.

Для анимаций используется длительность из Telegram, до 60 секунд. Первый декодированный кадр сохраняется всегда, в том числе у очень коротких видео-emoji; последующие выбираются с интервалом. Если длительность отсутствует, выбираются кадры начала файла; у видеостикера это может быть только начало анимации. TGS не рендерится целиком. Даже низкая оценка не описывает кадры вне выборки.

Файл скачивается внутри Telegram-адаптера. fal.ai получает только PNG data URI; Telegram download URL с токеном, file IDs и chat/user IDs не передаются. Личные подписи и текст не включаются. Секреты внутри самого изображения не маскируются.

## Кэш и ограничения

- Ключ общей проверки: хеш `file_unique_id` либо custom emoji ID, версии обработки и модели. Повторы ждут одну долговечную задачу и используют её результат после restart.
- Дополнительный SHA-256 кэш нормализованных кадров исключает новый вызов при одинаковых пикселях под разными file IDs. В production работает один media worker.
- `cache_days: 30`, допустимо 1–90 дней. Ошибка недоступности кэшируется на 15 минут, чтобы повторный спам не нагружал API.
- `daily_request_limit: 200` считает зарезервированные вызовы по UTC, включая неудачные попытки. Один новый анимированный файл может потребовать до трёх вызовов. Нулевой лимит оставляет доступными сохранённые результаты.
- Исчерпание бюджета оставляет задачу pending до следующего дня. В ЛС приходит одно уведомление об ожидании; окончательный результат придёт отдельно.
- До 30 новых заявок в минуту и 200 ожидающих заявок на чат. При перегрузке личка получает одно уведомление в минуту; группы увеличивают `sentinel_media_rate_limited_total`. Текстовые MUST jobs не зависят от этих лимитов.
- `max_file_bytes: 10485760` (10 MiB); максимальная настройка 20 MiB. PNG-кадр до 4 MiB, декодер ограничен 16 мегапикселями и 15 секундами. HTTP вызов модели: `timeout_seconds: 30`.
- 429/5xx, timeout и невалидный ответ повторяются с backoff. После восьми неудачных попыток результат недоступен, а не safe. В `visual_checks.last_error` и `result.error_code` сохраняется безопасный код причины, без тела ответа API, секретов и содержимого медиа. После неоднозначного сетевого timeout повторный платный вызов возможен; exactly-once не обещается.

`review_threshold: 0.35`, `nsfw_threshold: 0.75`: ниже первого порога низкий риск, между порогами нужна проверка, от второго высокий риск. Итоговый вердикт сохраняется с результатом, изменение порогов не переписывает старые кейсы. В группе известная повышенная оценка создаёт кейс даже при недоступности другого медиа. Результат без подозрения дополняет существующий кейс, но сам по себе новый не создаёт.

Очередь хранит данные до `retention.messages_days`; незавершённые медиа-заявки затем отменяются и очищаются. Это отдельная optional-политика, не политика обязательного текстового AI. `/metrics` показывает `sentinel_media_requests_pending` и `sentinel_media_calls_reserved_today`. Подробности удаления: [privacy.md](privacy.md).

## Проверка и откат

Тесты используют локальные fake Telegram/Fal API и отдельную БД. `ffmpeg` нужен для тестов реального PNG/JPEG/WebP/GIF/MP4/WebM-декодирования; Docker и CI содержат его. `go test ./...`, `go vet ./...`, `go test -race ./...`; миграции проверяются up/down/up.

Самый простой откат: `media.enabled: false` и пересоздание бота. Текстовый анализ продолжит работать. Очередь не обрабатывается, cleanup очищает её по TTL. Предыдущий бинарник совместим с добавленными таблицами. Для удаления схемы сначала остановите новый бинарник и сохраните backup: `migrations/0006_visual_moderation.down.sql` удаляет только visual-таблицы и все их данные. Не применяйте общий `migrations.Down` в production.
