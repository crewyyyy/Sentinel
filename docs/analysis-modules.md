# Модули анализа

Один анализатор готовит текст, запускает локальные модули и собирает оценку. Модули не обращаются к Telegram, БД или AI. Несколько сигналов создают одну AI-задачу на ревизию сообщения.

## Где менять

- `internal/rules/catalog.go`: модули, сигналы, обязательность AI, веса, словари и допустимые настройки.
- `internal/rules/detectors.go`: логика модулей. Новый модуль можно вынести в отдельный файл этого же пакета.
- `internal/rules/match`: общая нормализация и сопоставление текста.
- `internal/urlscan`: структурные факты ссылок и упоминаний; entities разбираются до маскирования текста.
- `internal/rules/analyzer.go`: дедупликация сигналов, caps, trust и итоговый score.

Каталог одновременно задаёт допустимые настройки и используется валидатором, поэтому отдельные списки модулей и кодов поддерживать не нужно. Посмотреть его без ключей и сетевых запросов:

```bash
go run ./cmd/sentinel modules
```

## Настройки YAML

Образец включает `referral_cues` и четыре модуля правил чата. YAML без `analysis` использует прежние настройки. При изменении каталога или настроек задайте новую `ruleset_version`.

```yaml
moderation:
  ruleset_version: my-rules-v2
analysis:
  modules:
    referral_cues:
      enabled: true
      matchers:
        query_keys:
          mode: exact
          terms: [ref, referral, affiliate, partner]
        bot_components:
          mode: token
          terms: [ref, referral]
    repetition:
      thresholds:
        recent_similar: 3
        recent_links: 4
  family_caps:
    repetition: 25
```

`terms` заменяет словарь выбранного matcher, а не дополняет его. Неизвестные поля, пустые словари и неверные диапазоны отклоняются. Перед заменой словарей обязательных категорий проверьте их покрытие на корпусе.

Режимы matcher:

| Режим | Сопоставление |
|---|---|
| `legacy_substring` | Подстрока; сохранён для точного воспроизведения v1 |
| `token` | Полный токен: `ref` совпадает с компонентом `REF_123_bot`, но не с `reference` |
| `phrase` | Последовательность токенов внутри одной части сообщения |
| `exact` | Полное значение, например имя query-параметра |

Все режимы используют lowercase и нормализацию `ё/е`. Токены разделяются пунктуацией и границей букв/цифр. Тело и цитата готовятся один раз; новые режимы не составляют фразу из конца тела и начала цитаты. Старый режим сохраняет прежнее поведение.

Обязательные `observation`, `links`, `commerce` нельзя выключить. Нулевой вес, cap или высокий trust не отменяют обязательный review. Остальные модули можно отключать через `enabled: false`. Порог `links.url_scan_limit` нельзя поднять выше лимита извлечения 32.

Контекстные модули `sales`, `distribution`, `services`, `recruitment` и приватная настройка по чатам описаны в [chat-modules.md](chat-modules.md). Они выключены в legacy defaults и явно включены в новом образце YAML.

## Что делает referral_cues

- Проверяет точные имена параметров ссылок без учёта регистра. Значения параметров для этого не нужны.
- Проверяет отдельные компоненты имени известного или предположительно бот-аккаунта в ссылке/упоминании.
- Создаёт `REFERRAL_REVIEW` с нулевым весом и обязательной AI-проверкой.
- Суффикс `bot` используется как эвристика.
- При обрезанном наборе признаков причина review — неполное покрытие.

Обычный `start` сам по себе не является новым ref-признаком. Существующие Telegram bot-link проверки продолжают работать отдельно. Лимиты структурных фактов: 32 ссылки, 32 упоминания и 32 имени параметров на ссылку; значения payload не дублируются в новых полях.

Лимит кандидатов учитывается до удаления дублей. Отброшенные/неразобранные ссылки отмечаются `urls_partial` и требуют review через обязательный links-модуль, даже если `referral_cues` выключен. Ошибка query parsing отмечает неполные query keys. Если маскирование или усечение изменило текст, производные URLs и mentions удаляются: без исходного контекста они могли бы раскрыть секрет вроде `password=@name`. Потерянное покрытие остаётся явным.

## Добавить кодовый модуль

1. Добавьте `Spec` в `Catalog()`: ID, версию реализации, сигналы, словари/пороги и `build`.
2. Реализуйте builder в пакете `rules`. Он получает уже проверенные настройки и возвращает чистые стадии `detectorFunc`.
3. Возвращайте `Finding{Code, Evidence, Confidence}`. Вес, mandatory и score назначает агрегатор; не вызывайте внешние сервисы.
4. Для текста используйте `in.matches(matcher)`, для отдельных значений — общий matcher. Не создавайте собственный lowercase или список `Contains`.
5. Добавьте положительные и отрицательные тесты, новую `ruleset_version`, затем validate/replay и перезапуск.

Порядок стадий задаётся `order`; текущие 10–70 сохраняют порядок сигналов v1. Опечатка в коде сигнала не теряется: агрегатор выдаёт обязательный `ANALYSIS_MODULE_ERROR`.

## Проверить и применить

```bash
# Без Telegram, БД, AI-ключа и платных запросов:
go run ./cmd/sentinel inspect --config configs/config.example.yaml \
  --file testdata/telegram_updates/promotion.json
go run ./cmd/sentinel replay --config configs/config.example.yaml \
  --file /path/to/reviewed-dataset.jsonl

# С production env, но без внешних запросов:
sentinel validate --config configs/config.yaml
```

`inspect`, `replay` и production используют один `Analyzer`. `replay` сохраняет прежние метрики порога; `IncompleteFeatures` отдельно считает старые или частично обезличенные samples. Ненулевое значение означает, что результат не подтверждает полноту новых extractors. Новые samples поддерживают цитату, счётчики повторов и версию признаков. Export не добавляет структурированные usernames и отмечает потерянное покрытие.

Снимок правил включает разрешённые настройки, версии движка/модулей и нормализацию. Изменённый снимок под уже записанной версией отклоняется. Старые оценки и pending AI payload не переписываются. Миграция `0004_module_settings` добавляет настройки чатов, панели и аудит; новые extracted facts по-прежнему живут в JSON.

Базовый YAML применяется после validate/replay и restart; новый код требует сборки. Переопределения через `/modules` применяются после подтверждения без restart, с отдельной неизменяемой версией анализа. Эталон `testdata/rules_v1_golden.json` фиксирует 101 полную оценку старого движка и не должен перегенерироваться ради прохождения тестов.
