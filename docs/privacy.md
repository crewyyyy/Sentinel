# Данные и privacy

Разместите в управляемой группе уведомление об обработке сообщений, целях, сроках и внешнем AI-провайдере. Уточните правовое основание, доступ администраторов и договорённости провайдера об использовании данных. Не включайте сервис незаметно для участников.

## Сроки

| Запись | Политика |
|---|---|
| Текст/редакции журнала | До 7 дней или последние 1000 сообщений/чат, более строгий критерий. Очистка при старте и раз в минуту; между очистками число может временно превышать cap |
| Evidence кейсов, feedback, reviews, reports, moderation events | По умолчанию 30 дней; отдельный `incident_days`, не бессрочный hold |
| Pending/processing mandatory job | Исключение: минимальный редактированный payload сохраняется до review. Причина — обязательность проверки. Следить за queue lag и доступностью провайдера; оператор должен устранять затяжной outage, не выдавать pending за проверенное |
| Daily aggregates и message_keys без текста | 90 дней по умолчанию |
| Processed inbox payload | Очищается сразу после successful processing; строки done удаляются после 7 дней |
| Update dedup IDs без текста | 90 дней, но не удаляются, пока на них ссылается inbox |
| First observed / lifetime counters | Chat-scoped факт наблюдения без текста сохраняется для устойчивости first-observed между рестартами и TTL. Удаляется по операторскому запросу |
| Authorization audit | 30 дней |
| Панель выбора модели | 30 минут; owner/destination/receipt и snapshot каталога, без ключей |
| Audit смены модели | 90 дней; actor и old/new model, без ключей |
| Текущая runtime-модель | До следующего явного выбора; не содержит токенов |

Медиа не скачиваются. Не сохраняется language_code/предполагаемая страна. Секреты конфигурации только env; логи не содержат body update, пользовательский текст, API keys или полные URL запросов Telegram. Текст, entities/URLs, quote/reply и AI-пояснение проходят redaction известных ключей/токенов, password assignments, email/телефонов. Это **не универсальный DLP**: неизвестный формат секрета или персональные данные в свободной форме могут остаться; нужен review политики и тестирование собственных форматов.

LLM получает ограниченный релевантный контекст, текст сокращён и помечается partial. Точные Telegram identifiers/usernames удаляются из структурных метаданных; авторы обозначаются локальными псевдонимами внутри job. Ссылки/упоминания внутри свободного текста могут всё ещё содержать идентификаторы. Текст всё ещё может идентифицировать человека. Не отправляйте весь backlog и не подключайте провайдера без разрешённой политики обработки.

## Удаление истории

Доступно оператору с доступом к серверу, не публичному HTTP endpoint:

```bash
# Подставьте chat/user IDs; не сохраняйте их в git или общих логах.
sentinel forget --config configs/config.yaml --chat <chat-id> --user <user-id>
```

Команда отказывает при retained case/pending job: обязательные данные не уничтожаются молча. В обычном случае удаляет сообщения/revisions/URLs, их assessments, jobs/reviews, reports пользователя и daily/chat stats. Для retained cases оператор сначала рассматривает сроки, относящиеся доказательства и запрос на удаление; незавершённую обязательную проверку не называют выполненной. Обезличивание ссылок на пользователя в других сообщениях/админ-аудите и очистка внешних экспортов требуют отдельного разбора, а не обещания «удалено везде».

Доставка Telegram уже отправленных карточек — отдельная копия за пределами БД. Сервис не вызывает deleteMessage даже для них: администраторы задают retention/autodelete закрытого чата и удаляют копии самостоятельно. Аналогично регулируйте TTL экспортов, backups и provider-side хранения. Шифрование диска/backup, firewall, отдельные DB credentials и ограниченный доступ к Docker обязательны для production.
